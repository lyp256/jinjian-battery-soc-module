# 电池 SOC 模块（银尔达 D700Tm / Air780EPM）

基于银尔达 D700Tm（Air780EPM 方案）的 LuatOS Lua 工程：把极空（JK）保护板的电池数据
转换成金箭电摩中控可读的 Modbus 从机数据，并通过 4G 以 MQTT 压缩上报。

1. **采集**：从极空 BMS 保护板 RS485 接口接收显示屏协议广播（2400 8N1，只收不发），
   协议见 [极空显示屏协议.md](../docs/jikong/极空显示屏协议.md)；
2. **协议转换**：作为 Modbus RTU 从设备（9600 8N1，从站地址 1）响应金箭中控的 BMS 查询，
   协议见 [金箭协议](../docs/jinjian)；
3. **上报**：通过 4G 连接 MQTT 服务器，每 30 秒把电池数据压缩聚合上报；编码采用
   列式 Delta + ZigZag + Varint + 游程压缩（`BMSStateHistory`），
   采集时间粒度以极空广播间隔为准。

> 开发参考：`Air780EPM v2026.03.24.12` 的文档与 demo。

## 1. 数据流与文件结构

```
极空保护板 ──RS4851 2400 8N1(只收)──► jk_display.lua ──"JK_ROUND"/一轮一条──► bms_uplink.lua
   （显示屏协议广播）                    解析/自检/失效标记                    14 条≈30s 一批
                                                                                  │ 压缩编码
金箭中控/仪表 ──RS4852 9600 8N1──► jinjian_slave.lua ──读缓存──┐                    ▼
   （Modbus RTU 主站，轮询 01 03/01/05/06）                     │        bms_codec.lua → MQTT
                                                               └── 同一份极空快照 ──4G→ <prefix>/<IMEI>/status
```

两个 485 通道互不影响：极空链路只收不发，金箭从机只应答主站请求，全部运行在 `sys`
协作式任务中，不用阻塞式等待。

| 文件 | 作用 |
|---|---|
| `main.lua` | 入口：PROJECT/VERSION、加载模块、等 4G 拨号后发布 `net_ready` |
| `config.lua` | 全部可调参数（串口/GPIO/波特率/MQTT/批次/阈值/日志开关） |
| `board.lua` | 板级资源：可控电压输出、NET LED、Reload 按键、硬件看门狗、供电电压、设备 ID/PN |
| `jk_display.lua` | 极空显示屏协议接收解析（帧定界、三类数据块、自检、数据失效标记） |
| `jinjian_slave.lua` | 金箭 Modbus RTU 从机（帧扫描、寄存器/开关量映射、写入、异常码） |
| `bms_uplink.lua` | 采样批次、双缓冲快照、压缩编码、MQTT 连接与发布、状态日志（`MQTT_HOST` 为空时整条链路不启动） |
| `bms_codec.lua` | `BMSStateHistory` 压缩编码器（列式 Delta+ZigZag+Varint+游程，自动选列模式与电芯布局） |
| `ntp_sync.lua` | NTP 对时（上报 `Time` 列依赖；联网后立即同步，之后每小时一次） |
| `tools/selftest.lua` | 离线自测（PC 端 Lua 5.4）：黄金向量、广播解析、从机应答、端到端上报 |

## 3. 极空广播解析要点

- 帧格式 `A5 5A | LEN | CMD | ADDR_H | ADDR_L | DATA(N)`，`LEN = N + 3`，帧总长 `LEN + 3`；
- 命令码：`0x82` = 写变量区（2B 大端地址 + 数据）；`0x80` = **写寄存器**
  （第 4 字节寄存器号 + 第 5 字节值）——寄存器 `0x01`（背光/刷新）是**轮起点**，
  寄存器 `0x02` 是**蜂鸣器帧**（报警时出现在轮尾，不能当轮起点，否则会把一轮截断）；
- 一轮顺序：写寄存器 → 主数据块 `82/1000`(96B) → [≥25 串] 第 25 节电压 `82/2011`(9B)
  → 单体颜色帧×27(216B) → 扩展块 `82/1300`(46B) → [报警时] 蜂鸣器帧；
- 轮字节数/周期随固件与串数变化（20 串 = 364B，≥25 串 = 373B，周期 0.5–2.2s）：
  解析严格按 `LEN` 定界，并用「CMD + LEN 必须是固定组合」过滤数据里的假帧头，
  从任意位置接入都能在一个帧内重新同步，不写死轮长/周期；
- 主数据块：总压(10mV)、电流(0.1A，充电为正)、SOC、最大压差、MOS 温度、电池温度、
  均衡开关、充/放电 MOS 状态、24 路单体电压(mV，未用槽位 0)、9 个图标位（= `sysAlarm` 位组合）；
- 扩展块：SOC 图标格数、折算剩余容量(0.1Ah)、**剩余时间 时/分/秒**（偏移 4/6/8）、
  **功率 u32 @偏移 10**(0.1W)、最高/最低/平均单体、**完整 `sysAlarm` u32 @偏移 20**、
  动画计数、**最大压差 @偏移 28**、**MOS 温度 @偏移 30**、系统报警/均衡开关/内部状态 A/B；
- 单体颜色帧：每串一个 RGB565 颜色码，
  `0x07E0` 绿=普通、`0x001F` 蓝=**最高单体**、`0xF800` 红=**最低单体**、`0x0000` 黑=未用槽位；
  解析为最高/最低单体序号与有效槽位数（诊断用，不参与串数判定）；
- 第 25 节电压帧 `82/2011`（仅 ≥25 串）解析为第 25 路单体，故串数上限 25；
- 自检与容错：`Σ单体电压 ≈ 总电压`（超差告警不丢弃）；扩展块偏移 28/30 与主块偏移 8/10
  交叉校验并计数；串数取最后一个 ≥ `JK_CELL_MIN_MV` 的槽位，变小需连续 3 轮确认
  （抗单节瞬时 0mV）；超过 `JK_DATA_TIMEOUT_MS` 无完整一轮则标记 `stale`，
  金箭从机仍用最后一次有效缓存应答。

## 4. 金箭 Modbus RTU 从机

寄存器映射与 ESP32 侧实现一致：

| 金箭寄存器 | 内容 | 来源 | 换算 |
|---|---|---|---|
| 0 | 总电压 | 广播总压 | mV / 10 → 0.01V |
| 1 | 电芯串数 | 广播识别串数 | 直传（金箭侧上限 24） |
| 2 | SOC | 广播 SOC | clamp 0–100 |
| 3 | 容量 | 估算总容量 | 剩余容量 ÷ SOC → Ah |
| 4 | 短路保护 | 短路报警位 | 0/1 |
| 5 | 充电电流 | 广播电流 | mA / 10 → 0.01A，充电为正 |
| 6/7 | 电池温度 2/1 | 广播电池温度 | 整数 ℃ |
| 8 | 板温 | 广播 MOS 温度 | 整数 ℃ |
| 9–32 | 单体电压 | 广播单体电压 | mV 直传，超出串数补 0 |
| 103 | 电池类型 | 固定 0（锂电） | `JJ_BATTERY_TYPE` |
| 104 | 循环次数 | 本地缓存（广播无此数据） | 默认 0 |
| 110 | 均衡状态 | 广播均衡开关 | 0/1 |
| 113 | 标称容量 | 估算总容量 | Ah |
| 1000–1007 | PN | 模块自身 PN（IMEI 后 12 位，形如 `SOC-234567890123`） | 16 ASCII |
| 1016/1017 | 版本 | 脚本 `VERSION` → a.b.c.d，`a高a低` / `b高b低` | 默认 0100/0000 |
| 1089 | 充电时间 | 本地缓存（默认 120 分钟，可写 0–120） | 分钟 |
| 1090 | 目标 SOC | 本地缓存（默认 90%，可写 0–100） | % |

保护开关量优先取扩展块的完整 `sysAlarm` 位图，缺扩展块时回退到 9 个图标位：

| 金箭开关量 | 含义 | sysAlarm 位 | 回退逻辑 |
|---|---|---|---|
| 4 | 短路保护 | bit7 `0x0080` 或 bit14 `0x4000` | 图标偏移 82 |
| 5 | 过温充电 | bit8 `0x0100` 或 bit1 `0x0002`(MOS 过温) | 图标偏移 78/80 |
| 6 | 过温放电 | bit15 `0x8000` 或 bit1 `0x0002` | 图标偏移 78/80 |
| 7 | 低温充电 | bit9 `0x0200` | 电池温度 ≤ `JJ_LOW_TEMP_CHARGE_C` |
| 8 | 低温放电 | 位表无专用位 | 电池温度 ≤ `JJ_LOW_TEMP_DISCHARGE_C` |
| 63 | 快充状态 | 充电中且电流 ≥ `JJ_FAST_CHARGE_CURRENT_MA`；主站写过"结束快充"后置 0，停充/放电后自动恢复判定 | — |

支持的应答：`01 03` 读寄存器、`01 01` 读开关量、`01 06` 写单寄存器（1089/1090）、
`01 05` 写单开关量（64 结束快充）；地址非法返回异常码 `02`，取值越界返回 `03`，
不支持的功能码返回 `01`，其它从站地址不应答。

> 金箭寄存器 `9–32` 只有 24 路单体：极空若为 ≥25 串，车端链路只暴露前 24 节，
> 第 25 节仍会进入 MQTT 压缩上报（`jk_display.MAX_CELLS = 25`）。

> 从机按标准 Modbus CRC 校验收帧（`docs/jinjian/02_BMS_PROTOCOL.md` §5 的 CRC 示例以标准计算为准）。

## 5. MQTT 压缩上报

- 开关：`config.lua` 的 `MQTT_HOST` 留空（默认值）即**关闭 4G 上报**——不建 MQTT 连接、不采样组批、
  不占用 `JK_ROUND` 事件，极空采集与金箭从机照常工作；填入地址（如 `MQTT_HOST = "399.run"`）
  后重新烧录脚本即启用；
- 主题：`<MQTT_TOPIC_PREFIX>/<device_id>/status`，`device_id` 优先取 IMEI，取不到用模组唯一 ID；
  `MQTT_HOST`/`MQTT_PORT`/`MQTT_IS_SSL`/`MQTT_USER`/`MQTT_PASSWORD` 与 QoS0 均在 `config.lua` 修改；
- 批次：一轮广播 = 一条样本，默认 14 条/批 ≈ 30s（`BATCH_SAMPLES` 可调）；串数变化时
  丢弃未满批次重新开始，保证"一批内串数固定"；
- 列内容：`temp1/temp2/tempMos`(0.1℃；广播只有一路电池温度，`temp1=temp2`)、
  `balanCurrent`(mA，广播无此数据填 0)、`batVol`(mV)、`batCurrent`(mA，充电为正)、
  `socCycleCap`(mAh，估算总容量)、`socCapRemain`(mAh)、`time`(Unix 秒) 与单体电压列
  （编码器自动在 offset/spatial 两种布局中取更短者）；
- `time` 取 NTP 对时后的 `os.time()`；首批样本前最多等 60s 对时，失败不阻塞采集；
- MQTT 未就绪时整批丢弃（QoS0、无本地堆积），断线由 `autoreconn` 自动重连；无 RPC/下行订阅。

## 6. 运行、烧录与运维

1. Luatools 新建项目，目录指向本 `air780epm` 文件夹（脚本在根目录，自动打包）；
2. 选择 Air780EPM 固件（需含 `mqtt`、`socket.sntp`、`air153C_wtd`、`adc`、`gpio` 等库）；
3. 下载脚本后自动运行，日志可见 `main jjsoc 1.0.0`、`jk uart 1 opened 2400 8N1 (RX only)`、
   `jj modbus rtu slave ready, uart 2 ... PN SOC-xxxxxxxxxxxx`；
4. 现场验证：USB-RS485 接 RS4852 模拟金箭主站（9600 8N1）轮询 `01 03 0000 0009`，
   或在 RS4851 上抓极空广播波形确认 2400 8N1 正常。

- NET LED：注册网络快闪 → 拨号成功慢闪 → MQTT 连上常亮；未配置 `MQTT_HOST` 时不会有 CONNACK，
  拨号成功后直接常亮（表示网络可用但不启用上报）；
- 周期日志：每 60s 打印采集/上报统计（轮数、样本数、批次数、发布/丢弃数、MQTT 状态）
  与供电电压（ADC0 换算值）；
- Reload 按键长按 3s 重启模组；硬件看门狗每 150s 喂狗（固件无 `air153C_wtd` 时打印告警后跳过）；
- 调试开关：`LOG_ENABLE`、`LOG_HEX_PAYLOAD`（整包 hex）、`LOG_RAW_FRAMES`（485 原始帧）。

## 7. 离线验证

工程自带 `tools/selftest.lua`，在 PC 上用 Lua 5.4 运行（不需要硬件）：

```powershell
cd air780epm
lua tools/selftest.lua
```

当前 131 项全部通过，覆盖：

1. `bms_codec` 黄金向量字节级比对（2 样本×3 电芯 = 41B；3 样本×2 电芯全静态 = 30B）；
2. 极空整轮 364 字节样本（见 `docs/jikong/极空显示屏协议.md` §7）逐字段核对：总压/电流/SOC/温度/单体/串数、SOC 图标格数、
   剩余时间 7:39:37（时/分/秒）、u32 功率、`sysAlarm` 位图、颜色帧（蓝=最高第 1 串、
   红=最低第 7 串、绿=普通、黑=空槽）、扩展块与主块交叉校验；并覆盖 37 字节分片接收、
   0x80/0x02 蜂鸣器帧不截断轮、≥25 串的 `0x2011` 第 25 节电压；
3. 金箭从机：文档 CRC 样例、`0-8`/`0-32`/`103-113`/PN/版本/开关量/快充应答、写充电设置与
   回显、越界异常 `03`、非法地址异常 `02`、非本机地址不应答；
4. 端到端：协程调度器真跑 `采样→批次→编码→发布`（14×20），并用独立实现的解码器
   把 MQTT payload 解回来逐条核对（含总容量 = 剩余容量 ÷ SOC）；
5. 上报开关：`MQTT_HOST` 留空时 `bms_uplink` 关闭上报——不采样、无上报主题、`flush` 拒绝、
   MQTT 未就绪（同一模块在配置地址后能正常上报，两种场景都覆盖）。

## 8. 已知取舍

| 项 | 说明 |
|---|---|
| 极空数据源 | 采用**显示屏协议广播**（2400 8N1 只收），不使用 JK Modbus 轮询；广播没有的字段（循环次数、名义容量、充电设置等）用本地缓存/推算，并可由金箭主站写入覆盖 |
| 采样粒度 | 一条样本 = 一轮广播（本机 ≈2.17s，轮周期随固件版本 0.5–2.2s 变化），一批 14 条 ≈ 30s，即"每 30 秒聚合上报" |
| 温度列 | 广播主块只有一路电池温度（固件按工况在 T1/T2 间取一个填入），`temp1` 与 `temp2` 填同一值，MOS 温度填 `tempMos` |
| 均衡电流 | 广播不提供，`balanCurrent` 固定 0 |
| 总容量 | 广播不提供，用 剩余容量 ÷ SOC 估算（SOC < 5% 时保持上次值） |
| 循环次数/循环容量 | 广播里没有，金箭 `reg104` 只能用本地缓存（默认 0） |
| 单体颜色帧 | RGB565 颜色码（非均衡线电阻表），本项目仅用于诊断 |
| 串数上限 | 主块 24 槽 + `0x2011` 第 25 节 = 25 路；车端金箭链路按协议只暴露 24 路 |
| 保留字段 | 扩展块偏移 36/38（内部状态 A/B）含义未定，只存不判 |
