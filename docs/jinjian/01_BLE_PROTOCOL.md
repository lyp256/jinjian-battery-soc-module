# 金箭智行 BLE 控制协议

> 适用对象：金箭蓝牙中控（FR508x）、仪表（VEHAUTO）、控制器（MC）、ABS、TFT、BMS。

---

## 1. 链路层（GATT）

| 项 | 值 |
|---|---|
| 广播名 | 16 位 ASCII（通常是车辆 SN，正则 `^[0-9A-z]{16}$`） |
| Service UUID | `0000FEE7-0000-1000-8000-00805F9B34FB` |
| Write 特征 | `000036F5-0000-1000-8000-00805F9B34FB` |
| Notify/Read 特征 | `000036F6-0000-1000-8000-00805F9B34FB` |
| CCCD | `00002902-0000-1000-8000-00805F9B34FB` |
| MTU | 建议 Android 请求 512；分包 >512 需自行拆包/排队 |

连接流程：

1. 扫描 → 按 16 位广播名匹配；
2. `connect` → 发现服务/特征；
3. 订阅 Notify（36F6）；
4. Android 设置 MTU 512；
5. 写 6 位随机 PIN（见 §4.3）；
6. 等 `FF` 识别帧（`FF01` 正常 / `FF02`、`FF03` 需重新配网，重新配网需用户按车上启动按钮确认）；
7. 登录（见 §3）；
8. 之后所有业务指令用会话密钥 key3 加密发送。

## 2. 明文帧格式（加解密前）

### 2.1 通用结构

```
┌────────┬──────────┬───────────┬──────────┬────────┬──────────┬──────────────┐
│ vehId  │ function │ address   │ num      │ count  │ data     │ CRC16 (LE)   │
│ 1 byte │ 1 byte   │ 2 bytes BE│ 2 bytes BE│1 byte  │ ...      │ 2 bytes      │
└────────┴──────────┴───────────┴──────────┴────────┴──────────┴──────────────┘
```

地址/数量均为大端（高字节在前），CRC16 为小端（低字节在前）。

### 2.2 各功能码的字段规则

| 功能码 | 名称 | 请求帧字段 |
|---|---|---|
| `01` | 读开关量 | vehId + 01 + address(2) + num(2) + CRC |
| `03` | 读寄存器 | vehId + 03 + address(2) + num(2) + CRC |
| `05` | 写单个开关量 | vehId + 05 + address(2) + value(2) + CRC（value=`FF00`/`0000`） |
| `06` | 写单个寄存器 | vehId + 06 + address(2) + value(2, 16 位有符号补码) + CRC |
| `0F` | 写多路开关量 | vehId + 0F + address(2) + num(2) + count(1, 字节数) + 位数据 + CRC |
| `10` | 写多寄存器 | vehId + 10 + address(2) + num(2) + count(1, 字节数=2×num) + data + CRC |
| `99` | OTA | 独立帧族，见 §9 |
| `60` | 音频操作 | 独立帧族，见 §9 |

> 注意：`05` 单开关量不带 `num/count`；`0F`/`10` 才带 count。与 Modbus 标准略有差异，请勿照搬标准库。

### 2.3 CRC16（Modbus）

初值 `0xFFFF`，多项式 `0xA001`，对“vehId 到 data 结尾”的明文计算，输出低字节在前：

```python
def crc16(data: bytes) -> int:
    crc = 0xFFFF
    for b in data:
        crc ^= b
        for _ in range(8):
            crc = (crc >> 1) ^ 0xA001 if crc & 1 else crc >> 1
    return crc

def crc_hex_le(data: bytes) -> str:
    c = crc16(data)
    return f"{(c & 0xFF):02X}{(c >> 8):02X}"   # 低字节在前
```

### 2.4 设备地址（vehId）

| 值 | 设备 |
|---|---|
| `01` | BMS 电池 |
| `02` | VEHAUTO 仪表/车联网 |
| `04` | ECU 蓝牙中控 |
| `05` | MC 电机控制器 |
| `06` | ABS |
| `09` | TFT 仪表 |
| `20` | 自定义设备 |
| `FF` | 识别帧（来自中控） |

## 3. 加密体系（AES-128-ECB）

### 3.1 静态基钥

```
AB 0E 05 5F 71 0A C6 E8 05 B6 30 9C CD EE 3B 5A
```

### 3.2 key2（设备密钥）

```
key2[i] = (BASE_KEY[i] + deviceName[i]) & 0xFF   // deviceName 为 16 个 ASCII 字符
```

### 3.3 key3（会话密钥）

1. 取当前时间戳 `Date.now()` 的后 8 位十进制字符串 `r`；
2. 生成 32 位 hex：`r + r + r + r`；
3. 每 2 位一组转数值：

```
key3[i] = (key2[i] + int(r_r_r_r[2*i:2*i+2], 16)) & 0xFF
```

### 3.4 登录报文

```
login = r(8 位十进制) + 手机号 12 位每字符 ASCII hex
```

- 手机号只保留数字，不足 12 位右侧补 `0`，超过 12 位取后 12 位；
- 共 32 个 hex 字符 = 16 字节，恰好一个 AES 块；
- 用 key2 加密发送（按 16 字节块，NoPadding）。

### 3.5 业务指令加密

所有业务指令（含 BMS 读取、质检配置、OTA 帧）：

1. 明文帧 hex → bytes；
2. AES-128-ECB + key3 + PKCS7 加密；
3. 加密后 bytes 写入 Write 特征 36F5；
4. Notify（36F6）收到的 bytes → hex → key3 + PKCS7 解密 → 得到明文帧 hex。

> 安全提示：ECB 无 IV、无 MAC，离线拿到基钥+设备名+时间即可算 key3；不要把设备名/时间因子暴露给不可信方。

## 4. 中控（ECU，vehId=04）可执行操作

### 4.1 基础控制（单开关量 05）

| 功能 | 地址 | 开 | 关 | 示例帧（明文） |
|---|---|---|---|---|
| 蓝牙无感开关 | `0001` | `FF00` | `0000` | `04050001FF00` + CRC(`DDAF`) |
| ACC 开机 | `0008` | `FF00` | `0000` | `04050008FF00` + CRC(`0DAD`) |
| 设防 | `0009` | `FF00` | `0000` | `04050009FF00` + CRC(`5C6D`) |
| 寻车 | `000A` | `FF00` | `0000` | `0405000AFF00` + CRC(`AC6D`) |
| 开坐桶 | `000B` | `FF00` | `0000` | `0405000BFF00` + CRC(`FDAD`) |
| 开龙头锁 | `000C` | `FF00` | `0000` | `0405000CFF00` + CRC(`4C6C`) |

### 4.2 读开关量 / 寄存器

| 操作 | 功能码 | 地址 | 数量 | 请求 |
|---|---|---|---|---|
| 读全部开关量 | `01` | `0000` | `0010`(16) | `0401000010` + CRC(`D5F0`) |
| 读 ECU 寄存器 | `03` | `0001` | `0018`(24) | `040300010018` + CRC(`1455`) |

开关量位定义（响应按位展开，bit0=LSB）：

- bit1 = 蓝牙无感开关
- bit8 = ACC 状态（1 开 / 0 关）
- bit9 = 设防状态

### 4.3 PIN 码发送

```
04 10 0012 0002 03 <6 位随机数字> + CRC
```

例：`04100012000203` + `123456`（共 `04100012000203123456`）+ CRC(`816C`)。

### 4.4 仪表时间设置（写多寄存器 10）

```
04 10 0064 0004 08 <年高><年低><月><日><时><分><秒>00 + CRC
```

年 = 16 位（高低字节反序），其余各 1 字节，末尾补 `00`。

例（2026-09-18 15:00:00）：`04100064000408 E607 09 12 0F 00 00 00` → `04100064000408E60709120F000000` + CRC(`9117`)。

### 4.5 质检/高级设置（checkMob，全部用 key3+PKCS7）

| 功能 | 功能码 | 地址 | 说明 |
|---|---|---|---|
| 写 SN | `10` | `0001` num=8 | 16 字符逐字符 ASCII hex |
| 仪表音量 | `06` | `0079`(121) | 16 位有符号，范围见页面 |
| 蓝牙配对开关 | `05` | `0066`(102) | `FF00`/`0000` |
| 新式配对 | `05` | 先 `000F`(15) 再 `0001` | 15：Android=0 / iOS·Harmony=1；再写配对开关 |
| 边撑关机 | `05` | `0026`(38) | `FF00`/`0000` |
| 边撑开机关闭 | `05` | `0025`(37) | `0000` |
| 坐人启动等 | `05` | 29–32、37–38 | `FF00`/`0000` 动态 |

## 6. 仪表（VEHAUTO，vehId=02）

### 6.1 读取

| 内容 | 功能码 | 地址 | num |
|---|---|---|---|
| SN/PN | `03` | `0001` | `0010`(16)，reg1–8=SN ASCII、reg9–16=PN ASCII |
| 功能位图 | `03` | `0021`(33) | `0001` |
| 车速 | `03` | `0031`(49) | `0001`，高 8 位为速度 |
| 里程/关锁次数 | `03` | `002A`(42) | `0003`：前 4 字节=里程(32bit BE)，后 2 字节=关锁次数 |
| 4G/定位状态 | `03` | `0044`(68) | `0001` 位解析 |

### 6.2 写入（均 2 字节大端、无补码，功能码 10）

| 功能 | 地址 | 取值范围 |
|---|---|---|
| 写 SN | `0001` num=8 | 16 字符 ASCII |
| 写 PN | `0009` num=8 | 16 字符 ASCII |
| 轮胎周长 | `0012`(18) | 628–2512 |
| 电机极对数 | `0013`(19) | 10–50 |
| 里程百分比 | `0014`(20) | 0–100 |
| 车辆功能配置号 | `0015`(21) | 16 位位图 |
| 最高速 | `0016`(22) | 由功能池约束 |
| 速度加/减 | `0017`(23) | bit7=负号，bit6..0=绝对值，-15~15 |
| 鞍座灵敏度 | `001A`(26) | 默认 70 |

| 里程/关锁（有 TFT） | `00EF`(239) | `[里程高16, 里程低16, 次数高16, 次数低16]` |

### 6.3 功能位图（寄存器 33）

16 位，LSB=bit0：

| 位 | 含义 |
|---|---|
| bit0 | 龙头锁感应 |
| bit1 | 坐桶感应 |
| bit2 | 坐人感应 |
| bit3 | 离车自动关机 |
| bit4–5 | 单击：00 无 / 01 Boost / 10 倒车 / 11 预留 |
| bit6–7 | 双击：00 无 / 01 推车助力 / 10 音乐 / 11 TCS |
| bit8–9 | 长按：00 无 / 01 倒车 / 10 预留 / 11 预留 |
| bit10–11 | 里程区：00 里程 / 01 电流 / 10 预留 / 11 预留 |
| bit12–13 | 电池区：00 SOC / 01 电压 / 10 温度 / 11 预留 |
| bit14 | 紧急制动双闪 |
| bit15 | 写入固定清 0 |

寄存器 34：bit0=开机密码禁用，bit2=车辆报失。

## 8. 响应解析

### 8.1 路由

解密后的明文首字节决定设备，次字节决定类型：

- 首字节 `04` → ECU，`01` → BMS，`05` → MC，`02` → VEHAUTO，`06` → ABS，`09` → TFT；
- 次字节为 `F0/F1/F2` → OTA 帧；
- 次字节为 `60` → 音频帧；
- 首字节 `FF` → 识别帧。

### 8.2 读寄存器响应（03）

```
vehId + 03 + byteCount(1) + data(byteCount 字节) + CRC(LE)
```

每 2 字节为 1 个寄存器，大端、16 位有符号（`>0x7FFF` 转负）：

```js
const v = parseInt(hex.slice(i, i+4), 16);
value = v <= 0x7fff ? v : v - 0x10000;
```

### 8.3 读开关量响应（01）

```
vehId + 01 + byteCount(1) + data(bit 数据) + CRC(LE)
```

按 LSB=bit0 逐位展开。

### 8.4 异常应答

功能码 `>0x80` 为异常：

```
异常功能码 = 原功能码 - 0x80
异常码：
  01 无效报文
  02 无效数据地址/长度越界
  03 写入值无效
  06 装置忙
```

### 8.5 VEHAUTO 自动上报（02 主动帧）

字段（hex 字符偏移）：

| 偏移 | 含义 |
|---|---|
| 8–16 | 状态位（ACC / 设防 / 蓝牙无感等） |
| 26–28 | 电源类型（00 铅酸 / 其它锂电） |
| 28–30 | SOC（`FF`=未知） |
| 30–34 | 续航里程（`FFFF`=未知） |
| 34–38 | 电压×0.1V（`FFFF`=未知） |

## 9. OTA 与音频（扩展帧族）

### 9.1 固件 OTA（F0/F1/F2）

1. **F0 握手**：`地址 + F0 + UpgradeSize + Manufacturer + Version + UpgradeCRC + CRC(LE)`
   - 应答：4 位状态 `0000` 成功 / `0001` 固件过大 / `0002` 厂商不匹配 / `0003` 版本错误。
2. **F1 分包**：`地址 + F1 + index(4 hex) + 128 字节数据 + CRC(LE)`
   - 每包 128 字节（256 hex 字符），不足补 `f`；
   - 应答：`index(4 hex) + status(4 hex)`，`0000` 成功 / `0001` 失败。
3. **F2 结果**：`地址 + F2 + CRC(LE)`，应答 4 位状态。

> CRC 全部为低字节在前。

### 9.2 音频操作（60）

| opcode | 操作 |
|---|---|
| `07` | 写内容握手：`04 60 07 <scene> <file_size 8hex> + CRC` |
| `08` | 分包数据（每包 128 字节） |
| `09` | 结果确认 |
| `0A` | 删除：`04 60 0A <scene> + CRC` |

## 10. 蓝牙调试模块开发清单

1. 扫描/连接/MTU/订阅 notify；
2. 计算 key2/key3、构造登录帧并加密；
3. 通用帧构造：读开关（01）、读寄存器（03）、写单开关（05）、写单寄存器（06）、写多开关（0F）、写多寄存器（10）；
4. CRC16（LE）+ AES-128-ECB（key3/PKCS7）；
5. 响应帧解析：CRC 校验 → 设备路由 → 读寄存器/开关量/异常/OTA 分支；
6. 建议维护请求 ID 映射（响应帧回显 address/num）做 Promise 超时；
7. 日志输出：明文帧、密文、key 派生中间量，便于排查。
