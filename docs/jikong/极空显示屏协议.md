# 极空(JK) BMS 显示屏接口协议

**协议**：锂电池主动均衡保护板显示器通信协议（成都极空科技）
**用途**：BMS → 原厂显示屏单向广播（2400 8N1）

---

## 1. 物理层与链路

| 项目 | 值 |
|---|---|
| 接口 | UART，电平标准 RS485（A/B） |
| 波特率 / 格式 | 2400 bps，8 数据位，1 停止位，无校验（8N1） |
| 字节序 | **大端**（高字节在前） |
| 链路方向 | 单工：保护板（主）持续广播，显示器（从）只收不发 |
| 帧间 | 轮内帧首尾相接，无间隙 |
| 轮周期 | 约 2 s（一轮 364 字节，**随固件与串数变化，不要写死**） |
| 校验 | **无 CRC / 校验和**，仅靠帧长度与帧头定界 |

---

## 2. 帧格式

```
┌─────────┬────────────┬───────────┬──────────────┬───────────────┐
│ A5  5A  │ 帧长度(1B) │ 命令码(1B)│ 起始地址(2B) │ 数据(N 字节)  │
└─────────┴────────────┴───────────┴──────────────┴───────────────┘
   帧头          LEN         0x80/0x82     大端 16 位       N = LEN − 3
```

* `LEN` = 命令码(1) + 起始地址(2) + 数据(N) = `N + 3`；**帧总长 = LEN + 3**；
* 无校验字段；用 `LEN` 与下一个 `A5 5A` 的位置互相定界；
* 命令码只有两个：`0x82` = **写变量区**（后跟 2 字节大端地址）；`0x80` = **写寄存器**（后跟 1 字节寄存器号 + 1 字节值，见 §3.1）。
* 一轮内固定出现下列块：

| 命令码 | 地址/寄存器 | LEN | 数据长度 | 内容 |
|---|---|---|---|---|
| `0x80` | 寄存器 `0x01` ← 值 `0x00` | `0x03` | 1 字节 | 寄存器写帧（每轮第一个帧）：轮起点/背光寄存器 |
| `0x82` | `0x1000` | `0x5D` | 90 字节（45×u16） | 主数据块：电压/电流/SOC/温度/状态/单体/报警 |
| `0x82` | `0x1300` | `0x2B` | 40 字节（20×u16） | 扩展块：剩余容量/功率/单体统计/剩余时间 |
| `0x82` | `0x2003+0x10k` | `0x05` | 2 字节 | 单体颜色帧 ×25（+2 个特殊状态帧）：最高/最低单体标记 |
| `0x82` | `0x2011` | `0x05` | 2 字节 | 第 25 节单体电压（**仅 ≥25 串的电池才发**） |

## 3. 数据块详解

下文"数据偏移"均指**数据块内**的字节偏移（数据块起点 = 帧内第 6 字节）。

### 3.1 寄存器写帧 `0x80`（6 字节）

| 帧内偏移 | 长度 | 值 | 说明 |
|---|---|---|---|
| 0 | 2 | `A5 5A` | 帧头 |
| 2 | 1 | `03` | LEN |
| 3 | 1 | `80` | 命令码：写寄存器 |
| 4 | 1 | `01` | 寄存器号 |
| 5 | 1 | `00` | 写入值 |

每轮第一帧恒为 `A5 5A 03 80 01 00`（寄存器 `0x01` ← `0x00`），用作轮起点。
`0x80` 帧的第 4~5 字节是**寄存器号 + 写入值**，不是 16 位地址。

寄存器语义（固件取值）：

| 帧 | 含义 |
|---|---|
| `A5 5A 03 80 01 40` | 寄存器 `0x01` ← `0x40`：开背光/唤醒显示 |
| `A5 5A 03 80 01 00` | 寄存器 `0x01` ← `0x00`：关背光/熄屏 |
| `A5 5A 03 80 02 64` | 寄存器 `0x02` ← `0x64`：触发蜂鸣器 |

### 3.2 主数据块 `0x82` + `0x1000`（96 字节）

数据块 = 45 个 u16（大端）：

| 数据偏移 | 名称 | 类型 | 单位 | 说明 |
|---|---|---|---|---|
| 0 | 电池电压 | UINT16 | 10 mV | |
| 2 | 电池电流 | INT16 | 0.1 A | 有符号，充电为正、放电为负 |
| 4 | 电池图标/充电动画状态 | UINT16 | - | 充电时 1/2 交替，放电/静置恒 3（不是 SOC/帧计数） |
| 6 | 剩余电量 | UINT16 | % | SOC |
| 8 | 最大压差 | UINT16 | mV | |
| 10 | MOS 温度 | INT16 | ℃ | 整数 |
| 12 | 电池温度 | INT16 | ℃ | 整数（固件按工况取 T1/T2） |
| 14 | 系统警告 | UINT16 | - | 0 = 无报警；1 = 有报警 |
| 16 | 单体平均电压 | UINT16 | mV | |
| 18 | 均衡开关状态 | UINT16 | - | 0 = 关闭；1 = 打开（功能开关，非"正在均衡"） |
| 20 | 充电 MOS 状态 | UINT16 | - | 0 = 关闭；1 = 打开 |
| 22 | 放电 MOS 状态 | UINT16 | - | 0 = 关闭；1 = 打开 |
| 24 | 单体电压[24] | 24×UINT16 | mV | 连续 24 个槽位，**未使用槽位 = 0** |
| 72 | 单体欠压报警 | UINT16 | - | 0/1；= sysAlarm 位 11（`0x0800`） |
| 74 | 电池已充满 | UINT16 | - | 0/1；= sysAlarm 位 4（`0x0010`） |
| 76 | 过流报警 | UINT16 | - | 0/1；= sysAlarm 位 6 或位 13（`0x2040`） |
| 78 | MOS 过温报警 | UINT16 | - | 0/1；= sysAlarm 位 1（`0x0002`） |
| 80 | 电池过温报警 | UINT16 | - | 0/1；= sysAlarm 位 8/9/15（`0x8300`） |
| 82 | 短路报警 | UINT16 | - | 0/1；= sysAlarm 位 7 或位 14（`0x4080`） |
| 84 | 协处理通信异常 | UINT16 | - | 0/1；= sysAlarm 位 10（`0x0400`） |
| 86 | 均衡线电阻过大 | UINT16 | - | 0/1；= sysAlarm 位 0（`0x0001`） |
| 88 | 串数不符合 | UINT16 | - | 0/1；= sysAlarm 位 2（`0x0004`） |

合计 90 字节（偏移 0~89）。

> 偏移 72~88 这 9 个"报警 0/1"不是独立状态，而是同一个 32 位 `sysAlarm` 位图的不同位组合；
> 完整位图见扩展块偏移 20（`u32`）。

### 3.3 扩展块 `0x82` + `0x1300`（46 字节）

数据块 = 20 个 u16（大端）：

| 数据偏移 | 字段 | 单位 | 说明 |
|---|---|---|---|
| 0 | SOC 电池图标等级 | 级 | 5 格图标的填充格数（与 SOC 对应），不是循环次数 |
| 2 | 折算剩余容量 | 0.1 Ah | 固件按 `剩余容量 × 配置容量 / 实际满充容量` 折算 |
| 4 | 剩余时间·小时 | h | 与偏移 6/8 组成 时:分:秒 |
| 6 | 剩余时间·分 | min | |
| 8 | 剩余时间·秒 | s | 0~59（60 进制借位） |
| 10 | 电池功率（u32） | 0.1 W | `u32(BE) @0x0A = 功率/100`（4 字节，起点在偏移 10） |
| 14 | 最高单体电压 | mV | |
| 16 | 最低单体电压 | mV | |
| 18 | 单体平均电压 | mV | 与主数据块偏移 16 对应 |
| 20 | 完整 `sysAlarm`（u32） | - | 32 位报警位图 |
| 24 | 动画/刷新计数 | - | 3 态循环 51/52/53，动画帧序号，不是测量值 |
| 26 | 充电动画状态 | - | 充电时 36→41 循环，放电/静置恒 29 |
| 28 | 最大压差 | mV | 与主块偏移 8 同源 |
| 30 | MOS 温度 | ℃ | 整数，与主块偏移 10 同源 |
| 32 | 是否有系统报警 | - | 0/1，与主块偏移 14 同步 |
| 34 | 均衡开关状态 | - | 与主块偏移 18 同步 |
| 36 | 内部状态字节 A | - | |
| 38 | 内部状态字节 B | - | |

### 3.4 单体颜色帧 `0x82` + `0x20xx`（每条 8 字节，每轮 27 条）

地址序列固定（每轮顺序完全一致）：

```
0x2003 0x2013 0x2023 … 0x2183   ← 步进 0x10，共 25 条 = 第 1~25 串的单体颜色
0x2203 0x2213                   ← 2 个特殊状态帧（不属于单体）
```

单条结构：

```
A5 5A 05 | 82 | 20 | 03 | 07 E0
 帧头    LEN 命令码 地址高 地址低  颜色值(2B, 大端, RGB565)
```

地址规律：`addr = 0x2003 + 0x10 × n`，`n = 0…24` → 第 `n+1` 串。

**数据不是测量值，而是 RGB565 颜色码**：

| 颜色值 | RGB565 | 含义 |
|---|---|---|
| `0x07E0` (2016) | 绿 | **普通有效单体** |
| `0x001F` (31) | 蓝 | **最高单体**（本轮电压最高的那一串） |
| `0xF800` (63488) | 红 | **最低单体**（本轮电压最低的那一串） |
| `0x0000` (0) | 黑 | **未启用 / 未使用槽位** |

> **红色缺失是正常现象**：固件在最低单体序号为 0（第 1 串）时多数轮次不写红色，
> 不要当丢帧或数据无效。颜色帧也不等于均衡线电阻表（这里只有 4 个离散颜色码）。

### 3.5 第 25 节电压帧 `0x82` + `0x2011`（仅 ≥25 串才发）

```
A5 5A 05 | 82 | 20 | 11 | <第25节电压 u16 BE, mV>
```

* 主数据块只带 24 个单体槽位；**单体数 ≥ 25 时**固件才额外发这一帧。
* 影响：≥25 串的电池**每轮字节数会比 364 多 9 字节**，用固定 364 切轮会漂移 → 必须按同步帧 + `LEN` 自适应。

## 4. 一轮时序（364 字节）

```
┌──────────┬──────────────┬────────────────────────────┬──────────────┐
│ 寄存器写 │  主数据块    │   单体颜色帧 27 条         │  扩展块      │
│  6 字节  │  96 字节     │      216 字节              │  46 字节     │
│ 80/01=00 │ 82/1000      │ 82/2003+0x10k              │ 82/1300      │
└──────────┴──────────────┴────────────────────────────┴──────────────┘
├──────────────────────── 1.517 s ─────────────────────────┤├─0.65s─┤
                                                             ↺ 循环 ≈2.17 s
```

| 序号 | 块 | 字节数 | 每轮帧数 |
|---|---|---|---|
| 1 | 寄存器写帧 `0x80` | 6 | 1 |
| 2 | 主数据块 `0x1000` | 96 | 1 |
| 3 | 单体颜色帧 `0x2003+0x10k` | 8 × 27 = 216 | 27 |
| 4 | 扩展块 `0x1300` | 46 | 1 |
| （可选） | 第 25 节电压 `0x2011` | 9 | 0/1（**仅 ≥25 串**） |
| （可选） | 蜂鸣器 `0x80 02 64` | 6 | 0/1（触发报警时） |

* 20 串：一轮恒 **364 字节**（位置：写寄存器 0→6、主块 6→102、颜色帧 102→318、扩展块 318→364）。
* 用写寄存器帧切轮：相邻两帧的字节偏移恒为 364；**≥25 串时要改成按实际字节数/时间自适应**（会多 9 字节）。

## 5. 解析伪代码

```c
// 环形缓冲区 b[]；数据块起点 d = 帧内第 6 字节；u16() 读大端
for (;;) {
    if (!(b[0] == 0xA5 && b[1] == 0x5A)) { drop(1); continue; }
    uint8_t  len  = b[2];                       // = N + 3
    if (available() < len + 3) break;           // 数据不全，等下一批
    uint8_t  cmd  = b[3];
    uint16_t addr = (b[4] << 8) | b[5];
    const uint8_t *d = b + 6;                   // 数据块

    if (cmd == 0x80) {
        /* 写寄存器：reg = b[4], val = b[5]（不是 16 位地址！）
           每轮第一帧恒为 reg=0x01 val=0x00 —— 一轮开始，重置轮内计数 */
    } else if (cmd == 0x82) {
        if (addr == 0x1000) {                   // 主数据块：45 个 u16
            v_bat_mv   = u16(d +  0) * 10;                 // mV
            i_bat_ma   = (int16_t)u16(d +  2) * 100;       // mA，充电为正
            soc_pct    = u16(d +  6);                      // %
            dv_max_mv  = u16(d +  8);                      // mV
            t_mos_c    = (int16_t)u16(d + 10);             // ℃
            t_bat_c    = (int16_t)u16(d + 12);             // ℃
            warn       = u16(d + 14);                      // 0/1
            v_cell_avg = u16(d + 16);                      // mV
            bal_sw     = u16(d + 18);                      // 0/1
            chg_mos    = u16(d + 20);                      // 0/1
            dch_mos    = u16(d + 22);                      // 0/1
            for (i = 0; i < 24; i++) v_cell[i] = u16(d + 24 + 2*i);   // mV
            for (i = 0; i <  9; i++) alarm[i]  = u16(d + 72 + 2*i);   // 0/1
        } else if (addr == 0x1300) {            // 扩展块：20 个 u16
            soc_icon   = u16(d +  0);                      // SOC 电池图标格数
            cap_remain = u16(d +  2) / 10.0f;              // Ah（折算剩余容量）
            chg_left_h = u16(d +  4);                      // 估算时间 时
            chg_left_m = u16(d +  6);                      // 估算时间 分
            chg_left_s = u16(d +  8);                      // 估算时间 秒
            power_w    = u32(d + 10) / 10.0f;              // W（u32！起点在 0x0A）
            sys_alarm  = u32(d + 20);                      // 完整 32 位报警位图
            v_max      = u16(d + 14);                      // mV
            v_min      = u16(d + 16);                      // mV
            v_avg2     = u16(d + 18);                      // mV
            anim       = u16(d + 24);                      // 3 态循环 51/52/53
            chg_anim   = u16(d + 26);                      // 充电时 36..41，其余恒 29
            dv_max_mv2 = u16(d + 28);                      // 最大压差，同主块 d+8
            t_mos_c2   = (int16_t)u16(d + 30);             // MOS 温度，同主块 d+10
            alarm_flag = u16(d + 32);                      // 0/1，同主块 d+14
            bal_sw2    = u16(d + 34);                      // 0/1，同主块 d+18
        } else if (addr == 0x2011) {            // 第 25 节电压（仅 >=25 串）
            v_cell[24] = u16(d);
        } else if (addr >= 0x2003 && addr <= 0x2183) {     // 单体颜色帧
            int n = (addr - 0x2003) / 0x10;                // 0..24 -> 第 n+1 串
            uint16_t c = u16(d);                           // RGB565
            cell_color[n] = (c == 0x07E0) ? COLOR_GREEN    // 普通有效
                          : (c == 0x001F) ? COLOR_BLUE     // 最高单体
                          : (c == 0xF800) ? COLOR_RED      // 最低单体
                          : (c == 0x0000) ? COLOR_BLACK    // 未用槽位
                          : COLOR_UNKNOWN;
        }
    }
    consume(len + 3);
}
```

## 6. 解析要点

1. **全部大端**；先读 `LEN` 定界，不要用固定偏移跳帧（颜色帧长度与主块不同）。
2. **无校验字段**：用三条自检兜底 ——「一轮 364 字节、块序固定」「颜色帧地址序列固定（25 条 + 2 特殊）」「Σ 单体电压 ≈ 总电压」。
3. **轮同步**：`0x80` 帧（恒为 `A5 5A 03 80 01 00`）出现即新一轮开始。它是**写寄存器**帧，不是"地址 0x0100 的同步帧"。
4. **单体数量**：主块固定 24 个槽位、颜色帧固定 25 条；未使用槽位主块为 0、颜色帧为黑(`0x0000`)。**≥25 串**时主块装不下，额外发 `0x2011` 帧（§3.5）。
5. **颜色帧只有 4 种码**：`0x07E0` 绿=普通单体、`0x001F` 蓝=最高单体、`0xF800` 红=最低单体、`0x0000` 黑=未用槽位。**按无符号 16 位读**（`0xF800` = 63488，不要当有符号 -2048）；同一时刻最多各 1 个蓝/红，且红经常整轮缺失——不要当丢帧。
6. **单体电压是 2 mV 栅格**，而平均/最高/最低可出现奇数——不要当成数据跳变。
7. **温度是整数 ℃**；**电流是 INT16、0.1 A、充电为正、放电为负**。
8. **广播里没有**：总容量、循环次数、循环容量、均衡电流、休眠时间、详细日志。需要时由外部来源补（例如总容量可由"剩余容量 ÷ SOC"推算）。
9. **不要与 JK 的 Modbus 协议混用**：Modbus 是 115200 8N1、CRC16、寄存器地址；本协议是 2400 8N1、无校验、块地址。
10. **扩展块里的"序号"是两个动画帧号**：偏移 24 = 动画/刷新计数（3 态 51/52/53）、偏移 26 = **充电动画状态**（充电时 36→41 循环、其余恒 29）——**不要当成测量值或循环次数**。
11. **主块偏移 4 = 电池图标/充电动画状态**（充电 1/2 交替，放电/静置恒 3），**不是帧计数、不是 SOC**。
12. **扩展块偏移 0 = SOC 电池图标格数**（51% → 3、92% → 5），**不是循环次数**。
13. **扩展块偏移 10~13 是一个 u32 功率**：`u32(d+10)/10` = W。只取偏移 12 的 u16 在 <6553.5 W 时数值相同，严格写法要看 4 字节。
14. **扩展块偏移 20~23 是完整 32 位 `sysAlarm`**，主块偏移 72~88 那 9 个"报警 0/1"是它的位组合（§3.2）。
